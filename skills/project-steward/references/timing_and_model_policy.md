# 作業に合うモデル・推論量

モデル・推論量を選ぶ時だけ参照する。通常・定期確認の実行と、連絡がなくても拾う手順は[定期確認](periodic_review.md)へ置く。

## 作業に合うモデル・推論量

| 呼ばれる場面 | 選択方針 |
| --- | --- |
| 定期候補取得、既知の形式の照合、受領確認 | 必要な正確さを満たす低コスト側。まず限定入力で確認する |
| 複数タスクの依存・矛盾確認、停止理由の整理 | 日常確認より推論を厚くする候補。必要な対象だけ読む |
| Butlerの横断優先判断、相反する根拠、権限・大きな損失に関する提案 | 判断能力を優先する。情報不足を高性能モデルだけで埋めない |
| 承認済みの定型的な引き渡し・反映確認 | 判断が済んだ範囲は低コスト側へ戻す |

モデル名・推論量は環境で相対的に選ぶ。Butlerは利用可能モデル、費用情報、確認日、作業別の推奨と理由を既存の運用記録に短く保持する。費用不明なら節約額を断定しない。毎回調査せず、利用可能モデル・費用・利用制限の変化、品質不足、確認期限を更新のきっかけにする。

設定変更は既存の承認と実行機能の範囲だけで行う。難しい一件のための一時変更か固定設定の変更かを区別し、一時変更なら戻す条件を持つ。設定された事実と品質・消費量の効果は別々に確認する。比較の連絡がない場合も期限で拾い、無結果を理由に他対象への適切な反映を無期限に遅らせない。製品本体は自動モデル切替や特定サービスの料金を保証しない。
